# Release 0.39 independent composition evidence

This directory owns 32 clearly labeled synthetic source contracts, 37 adversarial
harness self-tests and a separate reproducible GNU discrepancy probe. No upstream
example is rewritten or replaced. The feature-specific suites retain the original
M_intrinsics files, provenance and independent numerical corpus.

Final source verification: 32/32 candidate contracts pass; GNU executes 18,
compiles 8 without executing, and rejects 6 invalid programs. `results.json`
records the frozen candidate SHA-256, exact source hashes, commands, output,
status, diagnostics and summary counters. `gnu_checked` means compilation was
attempted; `gnu_skipped` means no compiler was requested. Thus compile-only is
not described as execution agreement. Expected errors never excuse host crashes.

Coverage includes AINT/ANINT KIND selection composed with ERF, ASINH/ACOSH,
Bessel operations, MINEXPONENT/MAXEXPONENT, ISO aliases, CSHIFT and ASSOCIATED;
rank1/2/3, pointer aliasing, zero-sized shapes, undefined and absent OPTIONAL
metadata operands, keyword order, declared source shadows, masked domains, and
atomic failure output. Rank3 values are checked element by element because the
preexisting reduction/RESHAPE subset is rank1/2. Fixtures use the existing
supported format, declaration, allocation and 132-column source rules.

The ordinary comparator is exact text or exact Decimal with signed-zero checks.
There is no float conversion, relative tolerance, ULP tolerance or Bessel
amplitude allowance in this runner. Nontrivial mathematical compositions use
only the explicit, documented rounding-bin invariants at x=1 (and the older
ERFC_SCALED x=0,1,2 invariants). They do not claim last-bit accuracy. Independent
ERF/Bessel mathematical accuracy belongs to its separate 1,818-point suite.

`test/test_release039_composition.f90` independently checks 13 new intrinsic
families inside a valid mixed-feature source, then corrupts type/kind, count,
slot, index, rank and cyclic metadata. Adapter, runtime and unevaluated KIND
must reject the mutants without output. A parser-free graph additionally
combines BESSEL_JN, result-kind AINT, CSHIFT and MINEXPONENT, checking exact
values/shapes and malformed descendants. Integration ran this unchanged source:
1,117 assertions passed; its log and exit status are copied here unchanged.

## Reproduce

From the repository root:

```
python3 tests/release039_integration/test_runner.py
python3 tests/release039_integration/run_tests.py --candidate /path/to/app --gfortran /path/to/gfortran
python3 tests/release039_integration/oracle-limitations/verify_discrepancy.py --candidate /path/to/app --gfortran /path/to/gfortran
fpm test --profile debug --target test_release039_composition
```

The runner verifies a fixed manifest SHA-256 and all source hashes before and
after execution, and snapshots a nonempty executable with a race check. Fixtures
are deterministically regenerated by `prepare_cases.py`; regeneration does not
silently update the runner's fixed manifest pin.

`initial-candidate-results.json` retains the first drafting-stage evidence.
Those fixture failures were unsupported existing syntax or diagnostic string
expectations, not a reason to change core semantics. The final receipt names only
`results.json`, the final harness log and the unchanged native evidence as final
pass evidence. Intermediate evidence is not misrepresented as a passing run.

## GNU optional-KIND discrepancy

The exact retained probe is copied byte-for-byte from the independent rounding
worker's synthetic probe. `oracle-limitations/independent-receipt.json` is our
separate replay on this merged app, at both GNU `-O0` and `-O2`. GNU runtime
AINT(1.999999999999d0,4) returns 2 and ANINT(0.499999999999d0,4) returns 1;
its constant folding and explicit round-then-assign form instead return 1 and 0.
The candidate returns the independent round-before-convert values, with exact
signed zeros checked too. This observation is not counted as GNU agreement.

GNU's primary [AINT](https://gcc.gnu.org/onlinedocs/gfortran/AINT.html) and
[ANINT](https://gcc.gnu.org/onlinedocs/gfortran/ANINT.html) descriptions apply the
rounding to A and identify KIND as the result kind. Decimal interval checks
cover binary64 input parsing error around these decimal inputs. The required
whole values are exactly representable in REAL4. No compiler-source explanation
is asserted. The ordinary runtime-narrowing source case remains compile-only;
the constant-folded source case remains a strict execution comparison.

These are bounded composition tests, not complete Fortran support. They do not
raise the existing 100,000,000-element array cap or claim that the unchanged
whole xutilities source executes.
