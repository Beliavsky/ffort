# Bounded TRAILZ and ISO integer availability

TRAILZ accepts supported INTEGER kind4/8 scalar and rank1–3 operands. It returns default INTEGER kind4 with the same elemental shape. Zero returns32 or64 according to the operand width; negative inputs are interpreted at that width. The runtime checks type, kind, range and shape before converting to a host integer. It does not negate a minimum signed value. The existing component/pointer/expression subset boundaries still apply.

`use[, intrinsic] :: iso_fortran_env, only: ...` additionally exposes immutable default-INTEGER INT8=-1, INT16=-1 and rank-one INTEGER_KINDS=[4,8]. These are this interpreter's actual capabilities, not host compiler kinds. Negative availability constants are not kind aliases and do not implement INTEGER(1)/(2); declarations, literal suffixes, typed constructors and conversions requesting unavailable kinds remain errors. Referenced constants, aliases, ONLY lists and existing source-module shadow rules are retained, never silently ignored. INTEGER_KINDS can be inspected as the bounded parameter array it is.

This follows [GNU ISO_FORTRAN_ENV documentation](https://gcc.gnu.org/onlinedocs/gfortran/ISO_005fFORTRAN_005fENV.html), which defines negative unavailable-kind constants and an array listing supported kinds, and the existing REAL128=-1 model. [TRAILZ documentation](https://gcc.gnu.org/onlinedocs/gcc-16.1.0/gfortran/TRAILZ.html) specifies elemental INTEGER input, default INTEGER output and full bit width for zero. Both references were checked2026-11-16.

All immutable descriptor flags, scalar/vector caches, type/kind, shape, bounds and element values are checked independently at runtime, including unused imports and KIND. Source adapter checks preserve exact remote/local pairs; changing INT8 to same-valued INT16 still fails source identity verification. Host-GNU's INT8/INT16 values and five-element INTEGER_KINDS are intentionally different. Those model tests have independent expected records or compile-only/rejection statuses, not false differential passes.

The unchanged pinned M_intrinsics demo_trailz is included with its MIT license and source SHA387a08537833bee3d7af1be7ec8c3a12dbde79cbfb4584ffc50c583429055f0c. Its existing/fresh GNU output is594bytes in10records, SHA5e56b38e9df96f853f4147ddebba861a5b970c978bb17f98e665c90199de26e9. Eight formatted/text records are byte-exact; only source-defined mixed record1 and integer record7 permit numeric field padding. At the preserved pre-validation stage, candidate whole-example acceptance was still pending rather than inferred; the final clean acceptance is now recorded in [verification](VERIFICATION.md#fresh-reconstructed-m_intrinsics-survey).

No POPCNT/POPPAR/BOZ/small-kind arithmetic, complex/effects, general module re-export or numeric-gather extension is included in this patch.

## Indexed availability constants and verification

INTEGER_KINDS is immutable rank-one default INTEGER [4,8]. Whole, element and section references retain scoped USE/ONLY/rename and host/local identity. INT8 and INT16 are -1 availability sentinels; they are not aliases for implemented arithmetic. Unsupported kind requests still fail. A source module preceding an omitted-nature USE can shadow the intrinsic module; a later source module does not retroactively capture that USE. Explicit INTRINSIC selects the intrinsic module.

The unchanged upstream TRAILZ demonstration executes with eight byte-exact formatted/text records and two narrowly normalized integer list-directed records. All 72 maintained source cases pass their specific contracts:40 successful executions, 30 exact static rejections and 2 exact runtime rejections. GNU stages remain separate: 29 executions, 24 compile-only, 16 ordinary compile rejections, 2 processor-shape rejections and 1 pinned backend defect. Native safety/producer programs pass 2053, 708, 16, 79 and 115 assertions. These focused results do not certify the full release.

Initial 66 sources and failed expectations are retained: two generated physical lines exceeded the documented 132-column limit and now remain explicit boundary cases with separately named continued variants; indexed INTEGER_KINDS exposed a genuine producer/ownership defect fixed by0115 and its adapter companion. The first producer 79 test incorrectly expected a triplet to be a call node; a separate AST observation established its array-slice representation before correcting the matcher. The original failed source and raw results remain preserved.
