# Independent read-only REPL reference review

Scope: inspected downloaded `/tmp/ofort-main-repl.c` and `/tmp/test-ofort-repl.py`, plus current `057-repl-session-work/src/fi_repl.f90`. No reference executable run, source edits, or full-parity claim. The underlying implementation of `ofort_reset` is not present in these two reference files, so its precise storage/RNG semantics are not established here.

## Observed reference control flow

- C 5844–5876: pending source is a byte suffix beginning at executed_len. It executes on the current interpreter; cursor advances to full buffer length only on success. Failure does not advance it. This alone does **not** prove rollback of partial variable/RNG effects on failure.
- C 5905–5937: a bare expression first executes that pending suffix, then executes the expression. Digit-leading expressions are parenthesized to avoid statement-label ambiguity. Bare queries are not appended to the buffer; expression-read tracking is updated only after query success (8334–8337).
- Consequently, a pending assignment/random draw can commit before an invalid query is diagnosed. Failed queries do not necessarily imply an unchanged session. Distinguish failure of pending execution itself from failure of the subsequent query.
- C 5939–5964: each `.run` iteration destroys/recreates the interpreter and executes the entire effective source. Caller 7647–7667 updates executed_len only if the run succeeds. `.run` is replay-from-fresh-state, not execute-only-new-source. A failed `.run` has already replaced the interpreter; no rollback guarantee is shown.
- C 5142–5185: every execute helper invokes ofort_reset and configures expression printing/output suppression/arguments. It emits returned output on success or special -2 status, yet returns success only for rc==0. Do not assume this reset means fresh variables: fresh interpreter construction is explicit elsewhere. Output-suppression details require library implementation or actual execution to establish.
- C 8435–8439: actual source selects immediate execution for top-level assignment, print and autorun candidates. The assignment classifier at4774 has no g_trace_assign condition, despite the help text's narrower wording. Read source rather than treating help as an exact execution specification.
- C 8470–8500: rejected preflight append restores source/cursor bookkeeping. A declaration appended after prior execution resets interpreter/cursor. Broader edit/load/autogenerated-block machinery is outside the bounded first subset.
- C 8526 onward: EOF executes the full effective buffer on the current interpreter and saves it. This is not a safe default to copy into a session that already executed pending work. `.quit`, `.quit!`, EOF and `.run` need separately specified policies.

Reference tests establish repeated .run argument handling (3684), uninitialized-value diagnostics (4494/4512), random harvest being treated as initialized (4530), and fresh replay for allocation via dot command (4630). They do not establish transactional rollback or exact pending-query failure side effects. The RNG examples use arrays, beyond the proposed scalar subset.

## Current bounded implementation difference

`fi_repl.f90:query_buffer` compiles/admit-checks both base and query before executing pending base. This is a defensible bounded rule, but differs from reference for syntax/admission-invalid queries: they leave pending source unexecuted. After successful pending execution, a runtime-failing read-only query still leaves that pending state committed. Do not describe every failed query as transactional or state-preserving.

`run_buffer` compiles first, then resets session before runtime execution; therefore a syntax-invalid `.run` currently retains the prior session, whereas an execution-failing `.run` starts from fresh state. Reference constructs a fresh interpreter before executing full source. Keep this explicit rather than claiming identical failure lifecycle.

## Required tests before claiming usable scalar sessions

1. **No replay on queries:** assign/increment scalar, query twice; value and state cursor stable. Queue scalar RANDOM_NUMBER, query twice; same observed harvest on both queries and exactly one consumed draw. Compare an independent next draw/control session, not just inequality of random outputs.
2. **Pending failures, two kinds:** pending RNG then syntactically invalid query; pending RNG then admitted runtime-failing expression (integer division by zero). Assert intended different commit behavior. A valid query after each establishes whether pending source was retained and executed exactly once.
3. **Execution failure:** pending increment/random draw followed by failing statement; repeat query. Decide/document whether failure poisons session, preserves a successful prefix, or rolls back. Never automatically replay potentially effectful prefix as a fallback. Test source length/cursor only advance on the approved commit condition.
4. **.run lifecycle:** complete run followed by repeated query; repeated `.run`; run after appended statements; syntax-invalid run versus runtime-failing run. Prove fresh replay semantics and no extra query replay. Avoid asserting that fresh ofort RNG draws equal FortFront draws; their RNG policies are separate.
5. **Read-only query contract:** reject user/intrinsic calls for this first slice, assignment/semicolon injection, statement fragments, arrays, components, procedures and hidden control-flow nodes before effects. Cover parentheses, quoted semicolon/exclamation, empty/comment-only input, malformed continuation and digit-leading literals. If `.true.`/`.false.` are accepted, distinguish logical literals from dot commands explicitly; reference's immediate-expression classifier excludes all dot-leading text.
6. **Definedness/types:** declared-but-uninitialized scalar query, CHARACTER kind/length, INTEGER4/8 overflow, REAL kind, LOGICAL output, repeated queries after failure. Undefined reads must not silently materialize defaults. Excluded PARAMETER/initializer/array/procedure/loop cases must fail before state/RNG/output effects, including declarations appended after a frozen session.
7. **State binding:** reject session reuse with changed source prefix, changed declaration names/types/kinds/lengths/order, forged instruction cursor or metadata, not merely differing instruction count. Bound total pending/source bytes, expression DAG work, state size and per-command steps. No hidden session persistence between unrelated API instances.
8. **Observable effects:** PRINT must not duplicate on query replay; no-output query failure should not emit a partial result. commit=false cannot undo output already written, so queries must be limited to the admitted final read-only expression print. Separate output behavior from state commit in tests.
9. **Unsupported commands:** `.vars` returns explicit unsupported diagnostic without flushing pending state or changing RNG/cursor. Reject `.run N`, `.time`, edits/load-state/etc unless explicitly implemented; never silently reinterpret as source or partially execute.
10. **Exit:** test `.quit` and EOF independently after already-executed/pending code. No accidental final replay or disk save borrowed from ofort unless specifically authorized and documented.

These are review findings and proposed tests, not observed FortFront or ofort runtime outcomes.
